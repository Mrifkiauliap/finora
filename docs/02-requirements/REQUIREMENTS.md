**Versi Dokumen**: 1.0.0

## Legenda Prioritas & Metode Verifikasi
- **Prioritas**: `P0` (Wajib untuk MVP), `P1` (Penting untuk MVP lengkap), `P2` (Peningkatan/pelengkap).
- **Metode Verifikasi**: `Unit Test`, `Integration Test`, `Component Test`, `E2E/Manual Browser`, `Security/Header Audit`, `Lighthouse/PWA Audit`.

## 1. Functional Requirements (`FR-001` – `FR-024`)

| ID | Nama | Deskripsi | Prioritas | Acceptance Criteria | Metode Verifikasi |
|---|---|---|---|---|---|
| **FR-001** | **Inisialisasi Basis Data & Zero-Signup Bootstrap** | Aplikasi menginisialisasi `FinoraDB`, melakukan *seeding* 13 kategori sistem dan `appSettings` default pada kunjungan pertama, lalu langsung membuka Dashboard tanpa login. | P0 | Saat `FinoraDB` kosong, pembukaan aplikasi menghasilkan 13 kategori (`isSystem=true`) dan 1 record `appSettings` (`id='default'`) secara idempoten dalam satu transaksi tanpa prompt autentikasi. | Integration Test, E2E/Manual Browser |
| **FR-002** | **Dashboard Ringkasan Finansial** | Halaman `/` menampilkan `NetBalance`, `AvailableBalance`, `TotalIncome(bulan ini)`, `TotalExpense(bulan ini)`, `SavingsRate(bulan ini)`, peringatan anggaran, progres target aktif, grafik ringkas, dan 5 transaksi terbaru. | P0 | Nilai angka di Dashboard cocok 100% dengan rumus `RULE-002` s.d. `RULE-005` dan `RULE-018`; menampilkan `"—"` saat `TotalIncome=0` dan empty state saat belum ada transaksi. | Integration Test, Component Test |
| **FR-003** | **Pembuatan Transaksi Baru** | Pengguna dapat mencatat transaksi `income` atau `expense` dengan nominal IDR integer positif, kategori aktif sesuai tipe, tanggal lokal `YYYY-MM-DD`, metode pembayaran, dan catatan opsional (≤ 500 karakter). | P0 | Input valid tersimpan ke tabel `transactions` dengan UUID v4 dan timestamp UTC; input tidak valid (≤ 0, desimal, kategori beda tipe) ditolak dengan pesan error spesifik di bawah field terkait. | Unit Test, Integration Test, Component Test |
| **FR-004** | **Penyuntingan Transaksi** | Pengguna dapat mengubah seluruh field transaksi eksisting dan memicu validasi tipe kategori bila `type` transaksi diganti. | P0 | Perubahan tersimpan dengan `createdAt` tetap dan `updatedAt` diperbarui; agregasi saldo dan anggaran bulan lama/baru langsung konsisten. | Integration Test, Component Test |
| **FR-005** | **Penghapusan Transaksi** | Pengguna dapat menghapus transaksi setelah mengonfirmasi pada dialog konfirmasi. | P0 | Record terhapus permanen dari `transactions` hanya jika konfirmasi disetujui; pembatalan mempertahankan record tanpa perubahan. | Integration Test, Component Test |
| **FR-006** | **Pencarian, Filter & Pengurutan Transaksi** | Pengguna dapat mencari berdasarkan catatan/nama kategori, menyaring berdasar rentang tanggal, tipe, kategori, metode pembayaran, serta mengurutkan tanggal/nominal di `/transactions`. | P0 | Hasil daftar dan subtotal pemasukan/pengeluaran selalu mencerminkan irisan seluruh filter aktif secara akurat; reset filter memulihkan tampilan bulan berjalan. | Integration Test, Component Test |
| **FR-007** | **Pengelolaan Kategori Kustom** | Pengguna dapat melihat kategori sistem dan membuat/mengubah kategori kustom (nama unik case-insensitive per tipe, ikon Lucide, warna terkurasi). | P0 | Duplikasi nama dalam `type` yang sama ditolak; kategori baru langsung muncul di pemilih formulir transaksi untuk tipe tersebut. | Unit Test, Integration Test |
| **FR-008** | **Arsip & Penghapusan Aman Kategori (*Reassignment*)** | Kategori yang direferensikan transaksi/budget/recurring tidak boleh di-*hard-delete* langsung; pengguna dapat memilih `isArchived=true` atau memindahkan seluruh referensi ke kategori lain bertipe sama secara atomik. | P0 | Kategori fallback `Lainnya` tidak dapat dihapus/diarsipkan; *reassignment* memperbarui 100% referensi di 3 tabel terkait dan menyelesaikan bentrok budget sebelum menghapus kategori asal. | Integration Test, E2E/Manual Browser |
| **FR-009** | **Pembuatan & Penyalinan Anggaran Bulanan** | Pengguna dapat menetapkan batas anggaran (`limitAmount > 0`) dan ambang peringatan (`50..95%`, default `80%`) per kategori pengeluaran per bulan `YYYY-MM`, serta menyalin anggaran dari bulan sebelumnya. | P0 | Maksimal 1 budget per `(categoryId, month)`; kategori bertipe `income` ditolak; fitur "Salin dari Bulan Lalu" hanya menyalin kategori yang belum memiliki anggaran pada bulan target. | Unit Test, Integration Test |
| **FR-010** | **Evaluasi Realisasi & Status Anggaran** | Sistem menghitung `BudgetSpent`, `BudgetRemaining`, `BudgetUtilizationPct`, dan status (`safe`, `warning`, `exceeded`) serta menampilkan transaksi penyumbangnya. | P0 | Status berubah tepat di ambang `warningThresholdPct` dan `> 100%` sesuai `RULE-009` dan `RULE-010`; pengubahan/penghapusan transaksi langsung merefleksikan nilai realisasi baru. | Unit Test, Integration Test |
| **FR-011** | **Manajemen Target Keuangan (*Financial Goals*)** | Pengguna dapat membuat, mengubah, menjeda/mengaktifkan, dan menghapus target keuangan dengan `targetAmount > 0` dan `deadline` opsional. | P1 | Target menampilkan `GoalProgressPct`, `RemainingTarget`, dan `RequiredMonthlySaving` (jika ada `deadline`) sesuai `RULE-018`; penghapusan target meminta konfirmasi dan menghapus `goalContributions` terkait secara atomik. | Unit Test, Integration Test |
| **FR-012** | **Kontribusi & Penarikan Earmark Target** | Pengguna dapat menyetor (`> 0`) atau menarik (`< 0`) alokasi dana pada suatu target melalui `goalContributions` tanpa membuat transaksi `expense`. | P1 | Setoran menaikkan `goal.currentAmount` dan mengurangi `AvailableBalance` tanpa menambah `TotalExpense`; penarikan yang membuat `currentAmount < 0` ditolak; `status` otomatis menjadi `'completed'` saat mencapai target. | Unit Test, Integration Test |
| **FR-013** | **Pengaturan Aturan Transaksi Berulang** | Pengguna dapat membuat, mengubah, menjeda/mengaktifkan, dan menghapus aturan berulang (`daily`, `weekly`, `monthly`, `yearly`) dengan `interval >= 1`, `startDate`, dan `endDate` opsional. | P1 | Aturan bulanan menyimpan `anchorDay` (1..31) dan menghitung pratinjau tanggal jatuh tempo berikutnya dengan *end-of-month clamping*; menonaktifkan/menghapus aturan tidak menghapus transaksi historis. | Unit Test, Integration Test |
| **FR-014** | **Materialisasi Lokal Idempoten Transaksi Berulang** | Sistem mengevaluasi aturan aktif ber-`nextRunDate <= today` saat bootstrap atau akses Dashboard/Recurring dan membuat transaksi jatuh tempo secara idempoten. | P1 | Eksekusi berulang pada hari yang sama tidak pernah menghasilkan duplikasi `(recurringRuleId, recurringOccurrenceDate)`; dibatasi maks 366 occurrence per satu kali eksekusi (`RULE-016`). | Unit Test, Integration Test |
| **FR-015** | **Visualisasi Grafik Analitik Interaktif** | Halaman `/analytics` menampilkan grafik tren pemasukan vs pengeluaran, grafik proporsi kategori pengeluaran, dan perbandingan periode menggunakan Recharts. | P1 | Grafik merender dataset agregasi tanpa error pada 0 data (empty state) maupun ratusan transaksi, dengan tooltip IDR terformat `id-ID` dan palet kontras aman. | Component Test, E2E/Manual Browser |
| **FR-016** | **Ringkasan Insight Keuangan Deterministik** | Sistem menghasilkan kartu wawasan finansial lokal (kategori terbesar, perubahan MoM pengeluaran, rasio tabungan, jumlah anggaran over-limit) secara deterministik tanpa AI/server eksternal. | P1 | Seluruh teks insight dapat diturunkan dari angka tabel lokal secara konsisten; tidak ada panggilan jaringan eksternal apa pun. | Unit Test, Component Test |
| **FR-017** | **Laporan Periode & Ekspor CSV** | Halaman `/reports` menampilkan ringkasan terstruktur siap cetak dan tombol ekspor `.csv` UTF-8 BOM dari transaksi pada filter terpilih. | P0 | Berkas CSV memuat header Bahasa Indonesia yang jelas, nominal angka valid, karakter berbahaya formula diawali tanda kutip tunggal (sanitasi formula injection), dan dapat dibuka rapi di spreadsheet. | Unit Test, E2E/Manual Browser |
| **FR-018** | **Preferensi Aplikasi & Tema Gelap/Terang** | Pengguna dapat mengganti tema (`dark`, `light`, `system`), hari awal minggu, ambang peringatan default, dan menyalakan/mematikan *privacy masking* saldo. | P0 | Perubahan tersimpan di `appSettings`, bertahan setelah reload, dan langsung mengubah token warna CSS / masking nominal seluruh layar. | Integration Test, Component Test |
| **FR-019** | **Penghapusan Total Data Lokal (*Factory Reset*)** | Halaman `/settings` menyediakan aksi hapus seluruh data lokal dengan konfirmasi ganda (mengetik kata kunci konfirmasi) dan opsi mengembalikan kategori default kosong. | P0 | Sebelum konfirmasi akhir diselesaikan, 0 data terhapus; setelah dikonfirmasi, seluruh tabel transaksi, budget, target, dan aturan berulang bersih di `FinoraDB`. | Integration Test, E2E/Manual Browser |
| **FR-020** | **Ekspor Backup JSON Terstruktur & Terverifikasi** | Pengguna dapat mengekspor seluruh 7 tabel `FinoraDB` ke berkas JSON berversi yang disertai SHA-256 checksum atas `payload` dan memperbarui `lastBackupAt`. | P0 | Berkas JSON lulus validasi envelope v1, memuat ke-7 tabel secara utuh, dan `checksum.value` cocok dengan hash SHA-256 `payload`. | Unit Test, Integration Test |
| **FR-021** | **Validasi & Pratinjau Impor Backup JSON** | Sebelum memulihkan data, sistem memvalidasi ukuran file, sintaks JSON, skema Zod ketat, versi format, dan checksum SHA-256 lalu menampilkan *Restore Preview*. | P0 | File rusak, checksum tidak cocok, versi tidak didukung, atau file `> 25 MB` ditolak tanpa memodifikasi `FinoraDB`; file valid menampilkan ringkasan jumlah record & konflik. | Unit Test, Integration Test |
| **FR-022** | **Eksekusi Restore Atomik (Mode Replace & Merge)** | Pengguna dapat menjalankan pemulihan dengan mode `Replace All` (konfirmasi ketik `"TIMPA"`) atau `Merge` (lewati atau perbarui konflik) secara atomik. | P0 | Kegagalan di tengah proses restore memicu rollback penuh Dexie; setelah sukses, 100% data pulih konsisten termasuk penyelesaian bentrok `(categoryId, month)` pada mode Merge. | Integration Test, E2E/Manual Browser |
| **FR-023** | **Pengingat Backup Berkala Lokal** | Sistem menampilkan indikator atau banner halus bila `lastBackupAt` kosong (ketika transaksi `>= 10`) atau sudah lebih dari 30 hari sejak backup terakhir. | P2 | Banner hanya menggunakan data `appSettings.lastBackupAt` dan jumlah transaksi lokal; dapat ditutup sementara dan langsung hilang setelah ekspor JSON berhasil. | Component Test, Unit Test |
| **FR-024** | **Navigasi Responsif & Quick Entry** | Aplikasi menyediakan sidebar responsif di desktop, bottom navigation + tombol cepat catat transaksi di mobile, serta dukungan navigasi keyboard. | P0 | Semua halaman aplikasi `/app/*` dapat diakses dari navigasi tanpa overflow horizontal pada lebar viewport `360px` hingga `1440px`. | Component Test, E2E/Manual Browser |
| **FR-025** | **Website Publik & Landing Page (`/`)** | Finora menyediakan halaman publik pada `/`, `/features`, `/about`, dan `/privacy` lengkap dengan 13 seksi landing page, mockup pratinjau statis, dan FAQ interaktif. | P0 | Landing page tampil di `/` dengan seluruh 13 seksi lengkap, dapat diakses responsif, dan FAQ accordion bekerja melalui klik/keyboard. | Component Test, E2E/Manual Browser |
| **FR-026** | **Pemisahan Rute & Navigasi Publik vs `/app`** | Navigasi website publik terpisah dari navigasi aplikasi keuangan; CTA `"Open My Finance"` mengarahkan langsung ke `/app` tanpa registrasi dan menginisialisasi `FinoraDB` hanya saat memasuki `/app`. | P0 | Mengklik `"Open My Finance"` membuka `/app` dan memicu `initializeApp()`; mengunjungi `/` tidak memanggil IndexedDB. | Component Test, E2E/Manual Browser |
| **FR-027** | **SEO, Metadata, Sitemap & Robots.txt** | Seluruh halaman publik memiliki judul, deskripsi, Open Graph, canonical URL, favicon, `sitemap.xml`, dan `robots.txt` yang memblokir pengindeksan `/app/`. | P0 | `sitemap.xml` hanya mencantumkan `/`, `/features`, `/about`, `/privacy`; `robots.txt` menyertakan `disallow: /app/`; metadata tidak membocorkan data pengguna. | Unit Test, Security/Header Audit |

## 3. Security Requirements (`SEC-001` – `SEC-010`)

| ID | Nama | Deskripsi | Prioritas | Acceptance Criteria | Metode Verifikasi |
|---|---|---|---|---|---|
| **SEC-001** | **Perlindungan Cross-Site Scripting (XSS)** | React escaping bawaan wajib dipertahankan; dilarang menggunakan `dangerouslySetInnerHTML`, `eval()`, `new Function()`, atau injeksi HTML mentah dari input pengguna maupun file backup. | P0 | Pemindaian statis (ESLint/grep) menunjukkan 0 penggunaan API sink berbahaya; input berisi `<script>alert(1)</script>` pada catatan/nama dirender sebagai teks biasa. | Unit Test, Security/Header Audit |
| **SEC-002** | **Validasi Skema Ketat pada Batas Sistem** | Seluruh input UI dan impor file JSON wajib melalui parser Zod `.strict()` sebelum diproses oleh service layer atau disimpan ke IndexedDB. | P0 | Field tak dikenal, tipe data salah, atau nilai di luar batas domain ditolak sebelum menyentuh `FinoraDB`. | Unit Test, Integration Test |
| **SEC-003** | **Perlindungan Prototype Pollution pada Impor JSON** | Parsing dan validasi berkas restore JSON wajib menolak atau mensterilkan kunci berbahaya (`__proto__`, `constructor`, `prototype`). | P0 | Berkas JSON berisi properti `__proto__` ditolak oleh skema Zod strict atau dibersihkan tanpa memodifikasi `Object.prototype`. | Unit Test, Security/Header Audit |
| **SEC-004** | **Verifikasi Integritas Checksum Backup** | Setiap berkas backup menyertakan SHA-256 checksum; proses impor memverifikasi kecocokan checksum sebelum mengizinkan pratinjau/restore. | P0 | Mengubah satu karakter pada `payload` JSON backup menyebabkan proses impor gagal dengan error integritas checksum. | Unit Test, Integration Test |
| **SEC-005** | **Pembatasan Ukuran & Tipe Berkas Impor** | Upload file restore dibatasi pada ekstensi/MIME `.json` dengan ukuran maksimal `25 MB` sebelum `JSON.parse` penuh guna mencegah hang/DoS memori tab browser. | P0 | Berkas > `25 MB` atau ekstensi non-JSON langsung ditolak oleh pengelola upload dengan pesan jelas. | Unit Test, Component Test |
| **SEC-006** | **Sanitasi CSV Formula Injection** | Nilai sel teks (`note`, `categoryName`) dalam ekspor CSV yang diawali `=`, `+`, `-`, `@`, `\t`, atau `\r` wajib dinetralkan (prefix `'`) dan di-quote sesuai RFC 4180. | P0 | Transaksi dengan catatan `=1+1` atau `=HYPERLINK("...")` diekspor dengan prefiks petik tunggal (`'=1+1`) sehingga tidak dieksekusi oleh Excel/Sheets. | Unit Test |
| **SEC-007** | **Penerapan 8 HTTP Security Headers Wajib** | Konfigurasi deployment Vercel (`next.config` / `vercel.json` / `middleware`) wajib mengirim ke-8 header keamanan wajib termasuk `Content-Security-Policy` yang ketat. | P0 | Inspeksi respons HTTP produksi Vercel menampilkan kedelapan header dengan nilai yang sesuai [SECURITY.md](../05-security/SECURITY.md), tanpa `'unsafe-eval'` di produksi. | Security/Header Audit |
| **SEC-008** | **Kebijakan Privasi Nol Transmisi & Nol Penyimpanan Server** | Tidak boleh ada API route server, log server yang menerima data pengguna, atau skrip eksternal yang mengirim data keuangan ke jaringan. | P0 | Pemeriksaan kode `src/app/api` (kosong/tidak ada) dan audit traffic jaringan membuktikan tidak ada data finansial yang meninggalkan perangkat. | Security/Header Audit |
| **SEC-009** | **Audit Keamanan Dependensi** | Dependensi npm diaudit berkala dan lockfile dikunci agar tidak memasukkan paket rentan kritis/tinggi ke bundel produksi. | P1 | `npm audit --omit=dev` (atau tool setara) tidak melaporkan kerentanan kritis yang dapat dieksploitasi tanpa mitigasi sebelum rilis. | Build & CI Check |
| **SEC-010** | **Konfirmasi Eksplisit untuk Aksi Destruktif** | Aksi hapus permanen berisiko tinggi (Restore `Replace All`, Factory Reset data lokal) memerlukan konfirmasi pengetikan kata kunci spesifik (`"TIMPA"` / `"HAPUS"`). | P0 | Tombol eksekusi tetap `disabled` hingga teks konfirmasi cocok persis (case-sensitive/trim). | Component Test, E2E/Manual Browser |

## 4. PWA Requirements (`PWA-001` – `PWA-007`)

| ID | Nama | Deskripsi | Prioritas | Acceptance Criteria | Metode Verifikasi |
|---|---|---|---|---|---|
| **PWA-001** | **Web App Manifest Lengkap** | Aplikasi menyediakan `manifest.webmanifest` valid dengan `name`, `short_name`, `start_url: "/"`, `display: "standalone"`, `theme_color: "#0B1220"`, `background_color: "#0B1220"`, dan ikon PNG `192×192`, `512×512`, serta `maskable`. | P0 | Chrome DevTools Application → Manifest melaporkan 0 error dan kriteria installability manifest terpenuhi. | Lighthouse/PWA Audit |
| **PWA-002** | **Registrasi & Siklus Hidup Service Worker** | Service Worker terdaftar aman pada HTTPS (dan localhost), menangani fase `install`, `activate` (pembersihan cache versi lama), serta pemberitahuan pembaruan ke pengguna. | P0 | Saat rilis baru tersedia, pengguna mendapat banner opsional "Pembaruan tersedia — Muat Ulang" dan tidak terjadi kondisi aset campuran rusak. | E2E/Manual Browser, Lighthouse/PWA Audit |
| **PWA-003** | **Caching Application Shell & Aset Statis** | Service Worker men-cache aset statis (`/_next/static/*`, font self-hosted, ikon) dan *application shell* sehingga aplikasi tetap terbuka saat offline. | P0 | Setelah kunjungan pertama, memuat ulang halaman saat mode Offline tetap menampilkan UI aplikasi fungsional dalam `< 1 detik`. | E2E/Manual Browser, Lighthouse/PWA Audit |
| **PWA-004** | **Isolasi Cache Service Worker dari Data Finansial** | Service Worker DILARANG keras menyimpan data transaksi, kategori, anggaran, target, atau file backup pengguna di `CacheStorage`. | P0 | Inspeksi DevTools Cache Storage menunjukkan hanya berisi aset aplikasi/statis dan rute UI, nol data JSON finansial pengguna. | Security/Header Audit, E2E/Manual Browser |
| **PWA-005** | **Halaman Fallback Offline (`/offline`)** | Aplikasi menyediakan rute `/offline` yang di-precache dan disajikan oleh Service Worker apabila navigasi dokumen gagal karena offline dan tidak ada di cache. | P0 | Navigasi ke rute yang belum di-cache saat offline menampilkan halaman `/offline` yang rapi dengan tombol kembali ke Dashboard. | E2E/Manual Browser |
| **PWA-006** | **Indikator Status Jaringan Non-Blocking** | UI menampilkan indikator status offline ringan saat koneksi terputus tanpa memblokir input transaksi atau kalkulasi lokal. | P1 | Mengaktifkan mode Offline memunculkan badge/banner "Offline • Data tersimpan lokal", dan seluruh form CRUD tetap berfungsi penuh. | Component Test, E2E/Manual Browser |
| **PWA-007** | **Dukungan Installability Desktop & Mobile** | Aplikasi memenuhi seluruh syarat installability PWA di Chromium/Android dan menyediakan meta tag Apple Web App untuk Safari iOS. | P0 | Prompt instalasi/ikon Install muncul di browser pendukung dan aplikasi berjalan di jendela `standalone` tanpa address bar browser. | Lighthouse/PWA Audit, E2E/Manual Browser |

## 5. Data Requirements (`DATA-001` – `DATA-008`)

| ID | Nama | Deskripsi | Prioritas | Acceptance Criteria | Metode Verifikasi |
|---|---|---|---|---|---|
| **DATA-001** | **Definisi Skema `FinoraDB` v1** | Basis data IndexedDB bernama `FinoraDB` versi 1 terdiri atas 7 tabel kanonik (`transactions`, `categories`, `budgets`, `financialGoals`, `goalContributions`, `recurringTransactions`, `appSettings`) dengan indeks sesuai [DATABASE_SCHEMA.md](../03-architecture/DATABASE_SCHEMA.md). | P0 | Inisialisasi Dexie.js menciptakan tepat 7 store dan seluruh compound index (`[type+date]`, `&$[categoryId+month]`, dll.) tanpa error upgrade. | Integration Test |
| **DATA-002** | **Representasi Nominal Integer Aman (IDR)** | Seluruh nilai uang disimpan sebagai integer JavaScript aman (`Number.isSafeInteger`), dengan transaksi `1..999_999_999_999` dan batas goal/budget `>= 1`. | P0 | Input float seperti `1000.5` atau angka melebihi `Number.MAX_SAFE_INTEGER` ditolak oleh skema Zod dan tidak pernah masuk ke `FinoraDB`. | Unit Test |
| **DATA-003** | **Standar Tanggal Kalender Lokal & Timestamp UTC** | Tanggal bisnis menggunakan `YYYY-MM-DD` (atau `YYYY-MM` untuk budget); timestamp audit sistem menggunakan ISO 8601 UTC (`...Z`). | P0 | Pengujian pada simulasi zona waktu UTC-8, UTC+0, dan UTC+7 (`Asia/Jakarta`) menghasilkan tanggal `date` dan pengelompokan bulan `YYYY-MM` yang konsisten tanpa pergeseran hari. | Unit Test |
| **DATA-004** | **Integritas Referensial Tingkat Aplikasi** | Aplikasi menjaga integritas `categoryId`, `goalId`, dan `recurringRuleId` di service layer karena IndexedDB tidak memiliki foreign key constraint bawaan. | P0 | Pembuatan transaksi/budget/recurring dengan `categoryId` fiktif ditolak; penghapusan goal menghapus kontribusinya secara atomik; penghapusan kategori terpakai wajib lewat *reassignment*. | Integration Test |
| **DATA-005** | **Keunikan & Idempotensi Kunci Bisnis** | Pasangan `(categoryId, month)` pada `budgets` dan `(recurringRuleId, recurringOccurrenceDate)` pada `transactions` dijaga unik. | P0 | Upaya menyisipkan dua budget untuk kategori & bulan sama di tolak/upsert terkontrol; materialisasi ulang tidak pernah menduplikasi transaksi berulang. | Integration Test |
| **DATA-006** | **Skema Envelope Backup JSON v1** | Format backup menyertakan `backupFormatVersion: 1`, `dbSchemaVersion: 1`, `appName: "Finora"`, `exportedAt`, `checksum`, dan `payload` lengkap seluruh 7 tabel. | P0 | Serialisasi ulang hasil ekspor selalu lolos validasi skema `BackupEnvelopeSchema` Zod secara bolak-balik (*round-trip*). | Unit Test, Integration Test |
| **DATA-007** | **Strategi Migrasi Skema Berversi** | Setiap perubahan skema `FinoraDB` di masa depan wajib menaikkan nomor versi Dexie (`version(n+1).upgrade(...)`) dan menyediakan migrator backup lintas versi di `backupService`. | P1 | Dokumen dan modul database memisahkan definisi versi sehingga upgrade v1 → v2 kelak dapat diuji dengan fixture data v1 tanpa kehilangan record. | Unit Test, Integration Test |
| **DATA-008** | **Penanganan Kuota & Persistensi Penyimpanan** | Aplikasi memantau status penyimpanan (`navigator.storage.estimate`), meminta `persist()` secara non-intrusif bila tersedia, dan menangani `QuotaExceededError` secara anggun. | P1 | Saat simulasi `QuotaExceededError`, aplikasi tidak crash, tidak korup data eksisting, dan mengarahkan pengguna ke halaman backup/pembersihan. | Integration Test, E2E/Manual Browser |
