# Test Cases Specification — Finora

**Versi Dokumen**: 1.0.0  
**Tujuan**: Daftar 40 kasus uji kanonik (`TC-001` – `TC-040`) yang memverifikasi seluruh kebutuhan pada [REQUIREMENTS.md](../02-requirements/REQUIREMENTS.md) dan dipetakan di [TRACEABILITY.md](../02-requirements/TRACEABILITY.md).

---

| Test ID | Skenario | Prasyarat | Langkah Pengujian | Hasil yang Diharapkan | Prioritas |
|---|---|---|---|---|---|
| **TC-001** | Inisialisasi pertama `FinoraDB` dan zero-signup | DB kosong | Jalankan `initializeApp()` / buka `/` di browser bersih | Terbentuk 7 tabel; terisi tepat 13 kategori (`isSystem=true`) dan 1 `appSettings` (`theme='dark'`); Dashboard tampil tanpa login. | P0 |
| **TC-002** | Idempotensi bootstrap berulang | `FinoraDB` sudah terinisialisasi | Panggil `initializeApp()` kedua kalinya | Kategori tetap 13 (tidak menjadi 26); pengaturan eksisting pengguna tidak tertimpa. | P0 |
| **TC-003** | Kalkulasi Dashboard bulan berjalan | Transaksi: Income 5.000.000, Expense 2.000.000 di bulan ini; Goal allocated 1.000.000 | Buka `/` atau panggil `getDashboardSummary` | `NetBalance=3.000.000`, `AvailableBalance=2.000.000`, `MonthlyIncome=5.000.000`, `MonthlyExpense=2.000.000`, `SavingsRate=60.0`. | P0 |
| **TC-004** | Kalkulasi `SavingsRate` saat Pemasukan = 0 | Hanya ada Expense 250.000 bulan ini, Income = 0 | Panggil `getDashboardSummary` dan render kartu Dashboard | `SavingsRate` bernilai `null`; UI menampilkan `"—"` (bukan `NaN`, `0%`, atau `-Infinity`). | P0 |
| **TC-005** | Tambah transaksi valid & format IDR | Kategori `cat-sys-food` aktif | Buka form transaksi, pilih `expense`, isi `35000`, kategori Makanan, tanggal lokal, Simpan | Tersimpan di `transactions` sebagai integer `35000`; UI memformat `Rp 35.000` dengan `tabular-nums`. | P0 |
| **TC-006** | Penolakan input nominal tidak valid | Form transaksi terbuka | Uji nominal `0`, `-5000`, `1250.5`, dan `1000000000000` (melebihi batas) | Validasi Zod menolak semua input; tidak ada record tersimpan; pesan error tampil di bawah input nominal. | P0 |
| **TC-007** | Isolasi tanggal kalender lokal lintas zona waktu | Simulasi jam lokal `01:30 WIB` (`18:30 UTC` hari sebelumnya) | Ambil `getLocalToday()` dan simpan transaksi | Tanggal tersimpan cocok tanggal kalender lokal WIB, tidak mundur 1 hari ke tanggal UTC. | P0 |
| **TC-008** | Edit transaksi & ganti tipe | Transaksi `expense` Rp 50.000 sudah ada | Ubah tipe menjadi `income`, pilih kategori `Gaji`, ubah nominal jadi `100000`, Simpan | `createdAt` tetap sama, `updatedAt` diperbarui, kategori lama tak lagi cocok ditolak bila belum diganti, saldo berubah `+150.000` dari sebelum edit. | P0 |
| **TC-009** | Hapus transaksi dengan konfirmasi | Minimal 1 transaksi ada | Klik Hapus → klik Batal; lalu klik Hapus → klik Konfirmasi Hapus | Batal mempertahankan record; Konfirmasi menghapus record dan memperbarui saldo & realisasi budget. | P0 |
| **TC-010** | Pencarian dan filter multi-kriteria | Ada 10 transaksi lintas tipe, kategori, metode, dan tanggal | Filter tipe `expense`, metode `e_wallet`, cari kata `"kopi"` | Hanya transaksi cocok yang tampil; subtotal filter menampilkan jumlah dan total nominal irisan filter tersebut. | P0 |
| **TC-011** | Penolakan rentang tanggal filter terbalik | Halaman `/transactions` | Masukkan `startDate = '2026-11-20'`, `endDate = '2026-11-10'` | Sistem menampilkan validasi rentang tanggal tidak valid dan tidak mengembalikan hasil salah. | P1 |
| **TC-012** | Buat kategori kustom & tolak duplikat | Halaman `/categories` | Tambah kategori `expense` `"Kopi"`; lalu coba tambah `" kopi "` di `expense`; lalu tambah `"Kopi"` di `income` | Yang pertama sukses; `" kopi "` di `expense` ditolak; `"Kopi"` di `income` diizinkan. | P0 |
| **TC-013** | Proteksi kategori fallback & soft-archive | Kategori sistem `cat-sys-other-expense` dan kategori kustom terpakai | Coba arsip/hapus `cat-sys-other-expense`; lalu arsipkan kategori kustom terpakai | `cat-sys-other-expense` ditolak; kategori kustom berhasil diarsipkan (`isArchived=true`), histori transaksi tetap tampil. | P0 |
| **TC-014** | Reassignment kategori atomik & bentrok budget | Kategori `C1` dan `C2` punya budget pada `2026-11` dan transaksi pada `C1` | Panggil `deleteCategoryWithStrategy(C1, { mode:'reassign', targetCategoryId: C2, mergeConflictingBudgets: true })` | Seluruh transaksi `C1` berpindah ke `C2`, budget `2026-11` pada `C2` tergabung tanpa melanggar indeks unik `&[categoryId+month]`, dan `C1` terhapus. | P0 |
| **TC-015** | Pembuatan budget & keunikan `(categoryId, month)` | Kategori pengeluaran aktif | Simpan budget `cat-sys-food` bulan `2026-11` Rp 1.000.000; coba buat record kedua untuk pasangan sama; coba pakai kategori `income` | Pasangan sama melakukan upsert/tolak duplikat sesuai kontrak; kategori `income` ditolak `RULE-008`. | P0 |
| **TC-016** | Salin anggaran dari bulan sebelumnya | Bulan `2026-10` punya 3 budget; `2026-11` sudah punya 1 budget untuk kategori A | Klik "Salin dari Bulan Lalu" di `2026-11` | 2 budget kategori B & C tersalin ke `2026-11`; budget kategori A yang sudah ada di `2026-11` tidak tertimpa. | P1 |
| **TC-017** | Evaluasi ambang status anggaran (`safe`, `warning`, `exceeded`) | Budget limit `1.000.000`, `warningThresholdPct=80` | Uji total spent: `799.999`, `800.000`, `1.000.000`, `1.000.001` | Berturut-turut menghasilkan status: `safe`, `warning`, `warning`, `exceeded` dengan `remaining = -1` pada kasus terakhir. | P0 |
| **TC-018** | Batas ambang peringatan validasi | Form budget | Uji `warningThresholdPct = 49` dan `96` | Keduanya ditolak oleh Zod; hanya `50..95` diterima. | P1 |
| **TC-019** | Kalkulasi target keuangan & estimasi bulanan | Goal `targetAmount=6.000.000`, `currentAmount=1.000.000`, `deadline` 60 hari ke depan | Panggil `listGoals(today)` | `RemainingTarget=5.000.000`, `GoalProgressPct=16.7`, `remainingMonths=2`, `RequiredMonthlySaving=2.500.000`. | P1 |
| **TC-020** | Setor kontribusi target tanpa double-counting & atomisitas | `NetBalance=5.000.000`, `TotalExpense=1.000.000`, goal `currentAmount=0` | Catat setoran `1.500.000` ke goal | `goal.currentAmount=1.500.000`, `AvailableBalance=3.500.000`, `TotalExpense` tetap `1.000.000`. | P0 |
| **TC-021** | Penolakan penarikan melebihi saldo target & auto-complete | Goal `target=1.000.000`, `current=800.000` | Coba tarik `900.000`; lalu setor `200.000` | Penarikan `900.000` ditolak; setelah setor `200.000`, `status` berubah otomatis menjadi `'completed'`. | P1 |
| **TC-022** | End-of-month clamping aturan berulang bulanan | Aturan `monthly`, `interval=1`, `anchorDay=31`, `startDate='2026-01-31'` | Hitung 4 jadwal berurutan | Menghasilkan `2026-01-31`, `2026-02-28`, `2026-03-31`, `2026-04-30`. | P1 |
| **TC-023** | Idempotensi materialisasi transaksi berulang | Aturan aktif `nextRunDate='2026-11-01'`, `today='2026-11-27'` | Jalankan `materializeDueTransactions('2026-11-27')` sebanyak 3 kali berturut-turut | Transaksi hanya dibuat tepat satu kali per occurrence date; eksekusi ke-2 dan ke-3 menghasilkan `generatedCount = 0`. | P0 |
| **TC-024** | Batas catch-up 366 occurrence & nonaktif pasca-`endDate` | Aturan `daily` ber-`startDate='2020-01-01'` dan aturan lain dengan `endDate='2026-11-05'` | Jalankan `materializeDueTransactions('2026-11-27')` | Aturan harian berhenti aman di 366 transaksi (`cappedRuleIds` berisi ID aturan); aturan ber-`endDate` berhenti setelah `2026-11-05` dan `isActive=false`. | P1 |
| **TC-025** | Agregasi analitik periode & dataset kosong | Dataset multi-bulan dan dataset 0 transaksi | Panggil `getAnalyticsReport` pada kedua dataset & render `/analytics` | Dataset terisi menghasilkan deret waktu & top kategori akurat; dataset kosong menampilkan empty state tanpa error Recharts. | P1 |
| **TC-026** | Insight engine deterministik lokal | Bulan lalu Expense `1.000.000`, bulan ini `1.250.000` | Panggil `buildDeterministicInsights` | Menghasilkan insight kenaikan pengeluaran `25%` dan kategori penyumbang terbesar tanpa panggilan jaringan. | P1 |
| **TC-027** | Ekspor CSV UTF-8 BOM akurat | 3 transaksi pada periode laporan | Klik Ekspor CSV di `/reports` | File `.csv` berawalan `\uFEFF`, jumlah baris = header + 3 transaksi, nominal dan label kategori cocok. | P0 |
| **TC-028** | Perlindungan CSV Formula Injection | Transaksi dengan catatan `=1+1`, `+cmd`, `@SUM(A1)` | Jalankan `serializeTransactionsToCsv` | Sel tersebut diawali `'` (`"'=1+1"`, `"'+cmd"`, `"'@SUM(A1)"`) di dalam output CSV. | P0 |
| **TC-029** | Pergantian tema Dark/Light & Privacy Masking | Halaman `/settings` & `/` | Ganti tema ke `light`, aktifkan `showBalancesMasked`, muat ulang halaman | Tema `light` dan masker `Rp •••••••` bertahan setelah reload. | P0 |
| **TC-030** | Factory Reset dengan konfirmasi ketik `"HAPUS"` | `FinoraDB` berisi 10 transaksi | Buka `/settings` → Reset Data → ketik `"hapus"` (huruf kecil) → ubah ke `"HAPUS"` | Tombol tetap disabled untuk `"hapus"`; aktif untuk `"HAPUS"`; setelah dieksekusi seluruh transaksi bersih. | P0 |
| **TC-031** | Ekspor Backup JSON lengkap & update `lastBackupAt` | `FinoraDB` berisi semua jenis entitas | Klik Unduh Backup JSON di `/settings/backup` | File valid `BackupEnvelopeV1` terunduh, memuat semua 7 tabel, `checksum.value` valid 64 hex, `appSettings.lastBackupAt` terisi. | P0 |
| **TC-032** | Penolakan Backup JSON dengan checksum dimodifikasi | File backup valid dari `TC-031` | Ubah 1 digit angka nominal di `payload` file JSON lalu unggah | `inspectBackupFile` menolak file dengan error `CHECKSUM_MISMATCH`; `FinoraDB` tidak berubah. | P0 |
| **TC-033** | Penolakan file berbahaya (Prototype pollution, >25MB, Zod invalid) | File JSON berisi `"__proto__":{"polluted":true}`, file >25MB, dan tipe string pada `amount` | Uji ketiganya di `inspectBackupFile` | Seluruh file ditolak sebelum restore preview; `Object.prototype` bersih dan DB aman. | P0 |
| **TC-034** | Restore `Replace All` & `Merge` atomik (plus rollback) | File backup valid & DB lokal berisi data berbeda | Uji `Replace All` (butuh ketik `"TIMPA"`), uji `Merge` (`skip_existing` vs `overwrite_existing`), serta simulasi error tengah transaksi | `Replace All` mengganti penuh; `Merge` menangani konflik `(categoryId, month)` tanpa duplikat; error tengah transaksi me-rollback penuh. | P0 |
| **TC-035** | Penolakan versi backup lebih tinggi | File JSON dengan `backupFormatVersion: 99` | Unggah di `inspectBackupFile` | Ditolak dengan `UNSUPPORTED_VERSION` dan pesan ramah. | P1 |
| **TC-036** | Benchmark kinerja 5.000 transaksi | Seed 5.000 transaksi selama 12 bulan di `fake-indexeddb` | Ukur waktu eksekusi `getDashboardSummary` | Rata-rata waktu eksekusi `<= 150 ms` (`NFR-001`). | P1 |
